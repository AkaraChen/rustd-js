# Native builds and frozen installs

Use the versions pinned in `package.json` and `.github/workflows/ci.yml`.
Run the same checks locally as in the native matrix:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
pnpm test:go
pnpm check:size
pnpm test:pack
```

Go must be on PATH when setting `RUSTD_GO=path`. The default local harness uses
`mise exec -- go`; CI uses setup-go. On a busy machine, build with
`CARGO_BUILD_JOBS=2 nice -n 10 pnpm build`. The Cargo cache is shared at the
repository's `target/`; each package still produces its own platform `.node`.

## Unpublished platform packages

The platform package manifests under `packages/*/npm/*` are generated by the
pinned napi CLI and committed as workspace members. pnpm links the matching
local versions through `linkWorkspacePackages` and `preferWorkspacePackages`.
The lockfile records these links while the parent package manifests retain
publishable semver optional dependencies. No protocol rewrite is needed during
publication, and no registry placeholder packages are required for development.

After changing a native package's version or targets, regenerate its platform
metadata and update the lockfile, for example:

```sh
pnpm exec napi create-npm-dirs --cwd packages/rustd-archive
pnpm install --lockfile-only
pnpm install --frozen-lockfile
```

Commit the parent manifest, platform manifests and lockfile together. Keep the
template package in the workspace: the Go smoke tests exercise its native code.

`napi artifacts` assembles the actual matrix outputs into these platform package
directories. `napi prepublish` retains the platform semver dependencies. To
validate preparation without publishing optional packages, use
`napi prepublish --skip-optional-publish` after assembling all configured targets.
Do not enable its GitHub release options during a preparation-only check.
`test:pack` installs tarballs made from the committed platform manifests into
clean consumers and checks the published parent dependencies and CJS/ESM loading.

## Platform reference behavior

- Go helper executables have `.exe` on Windows and are executed directly by
  absolute path. Spawn failures retain the operating system's error details.
- Generated JSON fixtures use LF on every checkout. Scanner fixture filenames
  are relative to GOROOT so installation paths cannot change the oracle.
- Go 1.24 ARM64 saturates an overflowing float-to-int64 conversion; amd64 does
  not. The native constant implementation follows the host Go behavior. Four
  ARM64 constant fixture files were generated on an actual ARM64 runner; the
  other fixtures are shared. The manual **Go constant fixtures** workflow and
  `scripts/generate-constant-fixtures.py` regenerate the full corpus.
- Go 1.24 ARM64 fuses the multiply-add in complex power's phase calculation.
  The native implementation matches it without changing the ULP limit.
- `tools/gofixtures/mathx-portability` reproduces a Go 1.24 ARM64 compiler issue
  where directly branching on a narrow reverse-bit result disagrees with
  printing that result. The Go verification harness materializes typed results
  across a non-inlined call before comparing the same values exactly. The manual
  **Mathx portability diagnostics** workflow runs the reproducer and all mathx
  tests on Linux ARM64 and macOS ARM64.
- System MIME defaults follow the host Go implementation: Unix files on Unix,
  registry Content Type values on Windows. Reload counts describe actual
  changes to the resulting default table.

The full **Native packages** workflow remains the artifact acceptance check;
the manual diagnostic workflows do not replace any of its gates.

### SMTP STARTTLS and unicode test memory

Windows cannot adopt a Winsock SOCKET through Node’s Unix-style `net.Socket({ fd })`. SMTP uses a Node-owned TCP stream on Windows from initial connection through TLS upgrade. The stream reader detaches its listeners before transferring ownership to TLS; native DATA dot-stuffing and every Go byte comparison remain in place. Unix keeps the native TCP transport. See the failed Windows job in run 34954842280 for the original `ERR_INVALID_FD_TYPE`.

The unicode test’s recode helper now copies each encoded rune immediately into a bounded output buffer instead of retaining one typed array per rune. It still visits every input rune and uses the same native decode/encode calls and byte/checksum assertions. This avoids the large retained object graph observed when the local test process was killed with SIGKILL.

Go multipart `Part.FileName` returns `filepath.Base` using host path rules. Tests compare that parsed field with the host basename, while preserving the complete filename in the exact wire-header comparison.

The existing checksum chi-square gate retains a random seed, one million samples per modulus and its original critical values. Its seed is now printed for diagnosis. Such a statistical gate can reject a random sample; a macOS ARM64 attempt reported chi-square 19.41176 against the unchanged 18.48 limit. The failure log is retained in the validation report.
